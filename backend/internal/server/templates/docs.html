Documentation

Vivant vous dit avec certitude qui est votre client : son identité est vérifiée sur sa carte nationale, son visage et son téléphone. Il confirme chaque partage sur son téléphone.

Démarrage rapide

  1. Créez un compte partenaire et copiez votre clé secrète (sk_test_…).
  2. Ajoutez l'adresse de retour de votre site dans votre tableau de bord.
  3. Faites deux appels : créer une vérification, puis lire le résultat.
1Votre serveur crée une vérification
2Vous redirigez le client vers url
3Il confirme sur son téléphone
4Il revient sur votre site, vous lisez le résultat

Créer une vérification

POST /v1/verifications

ChampTypeDescription
redirect_urltexteObligatoire. Adresse de retour enregistrée dans votre tableau de bord.
datalisteDonnées demandées, par exemple ["profile", "nin"]. Par défaut : ["profile"].
referencetexteFacultatif. Votre identifiant interne (dossier, client…), renvoyé tel quel.
 
curl {{.Issuer}}/v1/verifications \
  -H "Authorization: Bearer $VIVANT_SECRET_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "redirect_url": "https://votre-site.com/retour",
    "data": ["profile", "nin"],
    "reference": "dossier-42"
  }'

Réponse 201 : redirigez le client vers url. Le lien est valable 10 minutes et ne sert qu'une fois.

Lire le résultat

Après sa confirmation, le client revient sur votre adresse de retour :

https://votre-site.com/retour?verification_id=ver_7Kq2mXz9...&status=approved

Ne vous fiez pas au paramètre status de l'adresse : lisez toujours le résultat depuis votre serveur.

statusSignification
pendingEn attente de la confirmation du client.
approvedIdentité confirmée : identity est rempli.
deniedLe client a refusé, ou a choisi le mauvais code.
expiredLe client n'a pas confirmé à temps.

sub est l'identifiant unique de la personne pour votre service. Utilisez-le pour reconnaître un client qui revient.

Code complet à copier-coller

Une page « connexion » qui envoie vers Vivant, une page « retour » qui lit l'identité. Remplacez seulement votre clé et votre adresse.

// npm install express   (Node.js 18 ou plus)
const express = require("express");

const VIVANT_URL = "{{.Issuer}}";
const SECRET_KEY = process.env.VIVANT_SECRET_KEY; // sk_test_...
const RETOUR = "http://localhost:3000/retour";

const app = express();

// 1. Le client clique sur « Se connecter avec Vivant »
app.get("/connexion", async (req, res) => {
  const r = await fetch(`${VIVANT_URL}/v1/verifications`, {
    method: "POST",
    headers: {
      Authorization: `Bearer ${SECRET_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify({ redirect_url: RETOUR, data: ["profile", "nin"] }),
  });
  const verification = await r.json();
  res.redirect(verification.url);
});

// 2. Vivant renvoie le client ici après sa confirmation
app.get("/retour", async (req, res) => {
  const id = encodeURIComponent(req.query.verification_id);
  const r = await fetch(`${VIVANT_URL}/v1/verifications/${id}`, {
    headers: { Authorization: `Bearer ${SECRET_KEY}` },
  });
  const v = await r.json();

  if (v.status !== "approved") {
    return res.send("Vérification non aboutie.");
  }
  // Identité vérifiée : v.identity.family_name, v.identity.nin...
  res.send(`Bienvenue ${v.identity.given_name} ${v.identity.family_name}`);
});

app.listen(3000);
<?php
// vivant.php : à inclure dans les deux pages
const VIVANT_URL = "{{.Issuer}}";

function vivant(string $method, string $path, ?array $body = null): array {
  $ch = curl_init(VIVANT_URL . $path);
  curl_setopt_array($ch, [
    CURLOPT_CUSTOMREQUEST  => $method,
    CURLOPT_RETURNTRANSFER => true,
    CURLOPT_HTTPHEADER     => [
      "Authorization: Bearer " . getenv("VIVANT_SECRET_KEY"),
      "Content-Type: application/json",
    ],
    CURLOPT_POSTFIELDS     => $body ? json_encode($body) : null,
  ]);
  return json_decode(curl_exec($ch), true);
}

// connexion.php
require "vivant.php";
$v = vivant("POST", "/v1/verifications", [
  "redirect_url" => "https://votre-site.com/retour.php",
  "data"         => ["profile", "nin"],
]);
header("Location: " . $v["url"]);

// retour.php
require "vivant.php";
$v = vivant("GET", "/v1/verifications/" . urlencode($_GET["verification_id"]));
if ($v["status"] !== "approved") {
  exit("Vérification non aboutie.");
}
echo "Bienvenue " . htmlspecialchars($v["identity"]["given_name"]);
# pip install flask requests
import os
import requests
from flask import Flask, redirect, request

VIVANT_URL = "{{.Issuer}}"
HEADERS = {"Authorization": "Bearer " + os.environ["VIVANT_SECRET_KEY"]}

app = Flask(__name__)


# 1. Le client clique sur « Se connecter avec Vivant »
@app.get("/connexion")
def connexion():
    r = requests.post(VIVANT_URL + "/v1/verifications", headers=HEADERS, json={
        "redirect_url": "http://localhost:3000/retour",
        "data": ["profile", "nin"],
    })
    return redirect(r.json()["url"])


# 2. Vivant renvoie le client ici après sa confirmation
@app.get("/retour")
def retour():
    vid = request.args["verification_id"]
    v = requests.get(VIVANT_URL + "/v1/verifications/" + vid, headers=HEADERS).json()
    if v["status"] != "approved":
        return "Vérification non aboutie."
    return "Bienvenue " + v["identity"]["given_name"]


app.run(port=3000)

OpenID Connect

Vous utilisez déjà une bibliothèque OpenID Connect (Spring Security, Laravel Socialite, Passport, Django, .NET…) ? Vivant est un fournisseur standard : configurez-le avec l'adresse de découverte.

Découverte{{.Issuer}}/.well-known/openid-configuration
client_idVotre identifiant public pk_test_…
client_secretVotre clé secrète sk_test_…
Fluxauthorization_code avec PKCE S256 (obligatoire)
Scopesopenid + les données activées (profile, nin…)
Signatureid_token signé en RS256

Sécurité

  • Gardez la clé secrète sur votre serveur, jamais dans une application mobile ou du JavaScript.
  • Lisez toujours le résultat avec GET /v1/verifications/{id}, depuis votre serveur.
  • Utilisez HTTPS pour vos adresses de retour en production.
  • Régénérez la clé immédiatement si elle a pu fuiter.
